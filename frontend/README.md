# RecycleHub Frontend

หน้าบ้านจากแบบ Figma ของทีม ใช้ React + TypeScript + Vite เชื่อม Go / Gin API ใน `backend`

## เปิดใช้งาน

เปิด Docker Desktop ก่อน แล้วเปิด Terminal ที่รากโปรเจกต์ที่มีไฟล์ `docker-compose.yml`

**Terminal แรก — ฐานข้อมูลและ API**

```powershell
docker compose up -d postgres
go -C backend run ./cmd/server
```

**Terminal ที่สอง — หน้าบ้าน**

```powershell
cd frontend
npm install
npm run dev
```

เปิด http://localhost:5173 เลือกบทบาทและพนักงาน แล้วกดเข้าสู่พื้นที่ทำงาน
เปิดครั้งต่อไปใช้ `npm run dev` ได้เลย ส่วน `npm install` ใช้ครั้งแรกหรือเมื่อเพื่อนแก้ dependencies
ต้องมี Node.js 22.12+ หรือ 24 และเตรียม `backend/.env` ตาม [คู่มือ backend](../backend/README.md)

ถ้ายังไม่มีข้อมูลโรงงาน วัสดุ และพนักงาน สามารถเติมข้อมูลตัวอย่างด้วยคำสั่งเดิม:

```powershell
go -C backend run ./cmd/seed
```

รันคำสั่ง seed จากรากโปรเจกต์ ไม่ต้องรันทุกครั้งที่เปิดเว็บ

| `public/icons/` | ไฟล์โลโก้และไอคอนรูปภาพของทีม เช่น `Logo.png` ซึ่งใช้เป็นไอคอนแท็บเว็บด้วย |

| `src/components/` | เมนูด้านข้าง ส่วนหัว ปุ่ม ตารางสถานะ และหน้าต่างยืนยันที่ใช้ร่วมกัน |
| `src/components/Brand.tsx` | โลโก้และชื่อระบบที่หน้าเริ่มต้นกับเมนูด้านข้างใช้ร่วมกัน |
| `src/services/api.ts` | เรียก API และจัดการข้อความผิดพลาด |
| `src/context/` | ข้อมูลร่วมและผู้ใช้งานที่เลือกในหน้าทดลอง |
| `src/hooks/` | โหลดรายละเอียดรายการและยกเลิกคำขอเมื่อเปลี่ยนหน้า |
| `src/types.ts` | รูปแบบข้อมูลที่ตรงกับ DTO ของ backend |
| `src/styles.css` | สี ฟอนต์ และการจัดหน้าสำหรับคอมพิวเตอร์กับมือถือ |
| `tests/` | ชุดตรวจการเรียก API และส่งออก CSV |
| `vite.config.ts` | การเปิดเว็บและส่งคำขอ `/api` ไปที่ Gin |

## ลำดับทดลองใช้งาน

ไอคอนเมนูทั่วไปใช้ `lucide-react` ผ่านการ import ในไฟล์ component ไม่ต้องคัดลอกมาเก็บใน `public/icons/` โฟลเดอร์นี้เก็บเฉพาะไฟล์รูปที่ทีมใช้เอง อ้างรูปด้วย `${import.meta.env.BASE_URL}icons/Logo.png` ใน React เมื่อมีรูปเนื้อหาอื่นค่อยเพิ่ม `public/images/`

หัวหน้าขนส่งมีเมนู **พนักงานขับรถ** สำหรับเพิ่ม/แก้ข้อมูลและตั้งสถานะ ทำงานอยู่ / พักงาน / ลาออก คนขับต้องมีเลขใบขับขี่และวันหมดอายุที่ยังใช้ได้ก่อนมอบหมายงานใหม่ ข้อมูลเดิมที่ไม่มีใบขับขี่จะแสดงให้แก้ไขตามจริง และพักงาน/ลาออกไม่ได้ขณะมีงานอยู่ ดู [รายละเอียด API คนขับ](../backend/docs/drivers.md)

1. เลือก **พนักงานขาย** → โรงงาน → เพิ่มโรงงานหรือแก้ไขโรงงานเดิม → กรอกข้อมูลและปักหมุด → บันทึก จากนั้นสร้างคำขอซื้อโดยเลือกโรงงานและวัสดุได้เลย
2. ดูรายละเอียดคำขอซื้อ แล้วเปิดคำขอจัดส่งที่ระบบสร้างให้
3. กดชื่อผู้ใช้งานมุมขวาบน เปลี่ยนเป็น **หัวหน้าการขนส่ง**
4. เปิดคำขอรับ–ส่งวัสดุ → มอบหมายรถที่ว่างและคนขับ
5. เปลี่ยนเป็น **พนักงานขับรถ** คนเดียวกับที่ได้รับงาน → งานของฉัน
6. เปิดงาน → ดูแผนที่และกด **เปิดนำทาง** → เริ่มออกเดินทาง → ยืนยันจัดส่งสำเร็จ
7. ตรวจว่าคำขอซื้อเสร็จสิ้น และรถพร้อมใช้งานอีกครั้ง

การแก้ไขคำขอซื้อและที่อยู่ทำได้ก่อนจัดรถ การเปลี่ยนรถตามปกติทำได้ก่อนออกเดินทาง
เมื่อรถเสียหรือส่งมอบไม่ได้ คนขับกด **แจ้งปัญหาการขนส่ง** งานจะเป็น `on_hold` หัวหน้าขนส่งกด **แก้ไขปัญหา / เปลี่ยนรถ** เพื่อใช้รถเดิมต่อหรือมอบหมายรถใหม่ พร้อมบันทึกวิธีแก้ไข งานกลับไปสถานะก่อนแจ้งปัญหา รถเดิมที่เสียจะคง `maintenance` หากเปลี่ยนรถออก
หัวหน้าขนส่งยกเลิกได้ตอน `pending`, `assigned` หรือ `on_hold` โดยระบุเหตุผล สำหรับงาน `on_hold` ต้องยืนยันการประสานฝ่ายขายและจัดการวัสดุแล้ว คำขอซื้อจะไม่ถูกยกเลิกตาม และยังไม่มีการเปิดคำขอจัดส่งที่ยกเลิกแล้วใหม่ หากยังต้องส่งต่อให้ใช้การแก้ไขปัญหาแทนการยกเลิก
ฝ่ายขายเปิด **ติดตามการขนส่ง** เพื่อดูงานจากคำขอซื้อของตน หัวหน้าขนส่งจัดรถและติดตามสถานะ ส่วนการเริ่มเดินทางและยืนยันส่งสำเร็จเป็นของคนขับที่ได้รับงานเท่านั้น
API เปลี่ยนสถานะต้องส่ง `driver_id` ตรงกับประวัติการมอบหมายด้วย การตรวจนี้เป็นกติกาข้อมูลของเวอร์ชันทดลอง ยังไม่ใช่การยืนยันตัวตน: เมื่อเพิ่มระบบล็อกอินต้องใช้ตัวตนคนขับจาก session/token ฝั่งเซิร์ฟเวอร์แทนรหัสที่ client ส่ง

## ขอบเขตเวอร์ชันนี้

- ใช้ข้อมูลจริงจาก API ไม่มีการใส่ยอดขาย สต็อก หรือเวลานัดจำลองเพื่อเลียนแบบตัวเลขใน Figma
- หน้าพนักงานขายใช้คำขอซื้อ ไม่มีขั้นอนุมัติ ตามกระบวนการที่ทีมกำหนด
- หน้าเริ่มต้นเป็น **ตัวเลือกผู้ใช้งานสำหรับพัฒนา** ไม่ใช่ระบบล็อกอิน บทบาทในเว็บไม่ใช่การรักษาความปลอดภัย ต้องเพิ่ม authentication/authorization ฝั่ง backend ก่อนเปิดใช้กับผู้ใช้จริง
- ฝ่ายขายเพิ่มและแก้ไขโรงงานพร้อมพิกัดได้ที่หน้าโรงงาน ส่วนหน้าวัสดุยังเป็นการดูรายการ
- API ปัจจุบันเก็บวันนัดเป็นวันที่ ไม่มีเวลานัด, GPS สด, สต็อกคงเหลือ, ราคา, รายได้ หรือหลักฐานรูปภาพส่งมอบ จึงยังไม่ทำฟังก์ชันเหล่านั้น
- ไม่รวมปริมาณต่างหน่วยเข้าด้วยกัน และยังไม่มีการแปลงหน่วยเพื่อตรวจน้ำหนักเทียบความจุรถ
- แผนที่จัดส่งใช้พิกัดที่คัดลอกตอนสร้างคำขอ การแก้โรงงานภายหลังไม่ย้ายปลายทางของงานเดิม
- ฟอนต์ถูกติดตั้งผ่าน npm และให้บริการจากเครื่อง ไม่พึ่ง Google Fonts ขณะเปิดเว็บ
- อ้างอิงโครงสร้างและภาพจาก Figma ผ่านเบราว์เซอร์ เนื่องจากโควตา Figma MCP เต็ม จึงใช้ไอคอนจาก Lucide แทนการ export asset ต้นฉบับ

## การเชื่อมต่อและการตรวจสอบ

### แผนที่โรงงาน

ใช้ Leaflet + OpenStreetMap ไม่ต้องสมัครบัญชีหรือขอ API key ติดตั้งไลบรารีพร้อม `npm install` แล้ว
พิมพ์ชื่อโรงงาน ถนน หรือตำบลแล้วกด **ค้นหา** → เลือกผลลัพธ์ → ปรับหมุดให้ตรงทางเข้า → **ยืนยันตำแหน่งนี้** → บันทึกโรงงาน
ช่องตัวเลขอยู่ใน **กรอกพิกัดเอง / วางพิกัดที่คัดลอกมา** เป็นทางเลือกเมื่อค้นหาไม่เจอ การขยับหมุดหรือแก้พิกัดต้องยืนยันตำแหน่งใหม่
ปุ่ม **ตำแหน่งของฉัน** จะขอสิทธิ์อ่านตำแหน่งเมื่อกดเท่านั้น ควรใช้เมื่ออยู่ที่โรงงาน และต้องเปิดผ่าน localhost หรือ HTTPS
ชื่อและที่อยู่โรงงานที่กรอกจะไม่ถูกผลค้นหาเขียนทับ ควรตรวจที่อยู่ข้อความกับหมุดให้ตรงกันก่อนบันทึก
บริการค้นหาใช้ [Photon](https://github.com/komoot/photon#demo-server) โดยไม่ต้องสมัครหรือขอ API key สำหรับ demo นี้ ค้นหาหลังผู้ใช้กดปุ่มเท่านั้น และใช้ขอบเขตบริเวณประเทศไทย
ผลค้นหาอาจไม่ครอบคลุมทุกโรงงาน ถ้าไม่พบให้ค้นหาถนน/ตำบลใกล้เคียงแล้วปรับหมุด หรือกรอกพิกัดเอง
API จำกัดการเรียกผู้ให้บริการรวมไว้หนึ่งคำขอต่อวินาทีและครั้งละหนึ่งคำขอ พร้อมแคช 1 ชั่วโมงสูงสุด 200 คำค้นต่อโปรเซส
Photon สาธารณะอนุญาตการใช้งานในปริมาณเหมาะสม แต่ไม่รับประกันความพร้อมให้บริการ หากขยายระบบให้เปลี่ยน `GEOCODER_URL` ใน `backend/.env` ไปยัง Photon instance ของตน/ผู้ให้บริการ และรีสตาร์ท API; หลาย instance ต้องมี rate limit ร่วมกัน

โรงงานเดิมที่ยังไม่มีพิกัดจะแสดง **ยังไม่ได้ปักหมุด** ให้ฝ่ายขายแก้ไขหนึ่งครั้งก่อนสร้างคำขอใหม่
พิกัดใน seed เป็นเพียงตัวอย่าง ไม่ใช่ตำแหน่งโรงงานจริง และ seed จะไม่ทับข้อมูลโรงงานที่มีอยู่แล้ว
คนขับดูชื่อปลายทางบนแผนที่ในงานของตน และกด **เริ่มนำทาง** เพื่อเปิดเส้นทางรถยนต์ใน Google Maps โดยไม่ต้องใช้ API key
กด **เต็มจอ** เพื่อขยายแผนที่ทั้งบนมือถือและคอมพิวเตอร์ กด **กลับมาที่หมุด** เมื่อเลื่อนออกจากปลายทาง และกดปิดหรือ Escape เพื่อกลับหน้าเดิม พิกัดตัวเลขอยู่ใน **ดูพิกัดปลายทาง**
ตอนเพิ่มหรือแก้ไขโรงงานสามารถเลือก/ลากหมุดในแผนที่เต็มจอ แล้วกลับมายืนยันตำแหน่งก่อนบันทึกได้ การขยายหรือปิดแผนที่ไม่บันทึกโรงงานอัตโนมัติ
ปุ่ม **ใช้ตำแหน่งของฉัน** ในแบบฟอร์มโรงงานแสดงค่าความคลาดเคลื่อนที่อุปกรณ์รายงาน เพื่อให้ตรวจหมุดก่อนยืนยัน
ระบบยังไม่ได้ติดตามรถแบบ GPS สดหรือคำนวณเส้นทางสำหรับข้อจำกัดรถบรรทุก

แผนที่ต้องใช้อินเทอร์เน็ตและแสดงเครดิต OpenStreetMap ตาม [นโยบาย tile](https://operations.osmfoundation.org/policies/tiles/)
เซิร์ฟเวอร์สาธารณะให้บริการแบบ best effort ไม่รับประกันหรือรองรับปริมาณใช้งานไม่จำกัด ห้ามดาวน์โหลดแผนที่เป็นชุดเพื่อใช้ offline
ถ้าขยายสู่ระบบผู้ใช้จำนวนมาก ให้เปลี่ยนผู้ให้บริการ tile และเครดิตให้ตรงข้อกำหนด (URL กำหนดได้ด้วย `VITE_MAP_TILE_URL`)
อ้างอิง [Leaflet](https://leafletjs.com/examples/quick-start/) และ [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)

### API

เว็บเรียก `/api/...` บน origin เดียวกัน แล้ว Vite ส่งต่อไป `http://127.0.0.1:8080` พร้อมตัด `/api` ออก
Postman ยังใช้ URL เดิม เช่น `http://localhost:8080/trucks` ไม่ต้องเปลี่ยน backend หรือเปิด CORS เพิ่ม

ถ้า API อยู่พอร์ตอื่น ตั้งค่าเฉพาะตอนรัน Vite เช่น:

```powershell
$env:API_TARGET = "http://127.0.0.1:8081"
npm run dev
```

```powershell
npm run build
npm test
npm run format
```

`npm run preview` ใช้ดูผล build ในเครื่องที่พอร์ต 4173 และเชื่อม API เดิม
เมื่อนำเว็บไป deploy ต้องให้เว็บเซิร์ฟเวอร์ส่ง `/api/*` ไปที่ backend และส่ง `index.html` สำหรับเส้นทางหน้าบ้านที่ไม่ใช่ไฟล์
ไฟล์ `dist/` เป็นผล build และ `node_modules/` เป็น dependencies ไม่ต้องนำขึ้น Git

อ้างอิงเครื่องมือ: [React](https://react.dev/learn/build-a-react-app-from-scratch), [Vite](https://vite.dev/guide/)
